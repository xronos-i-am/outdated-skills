# outdated-skills

Хук старта сессии: сообщает агенту об отставших зависимостях apm.yml проекта

## Установка

```bash
make install
```

## Что сообщает хук

Хук `SessionStart` запускает в каталоге сессии `COLUMNS=250 apm outdated` и передаёт агенту в контекст строки со статусом `outdated`: зависимости `apm.yml`, у которых вышла версия новее записанной, — как свои, так и чужие пакеты, записанные тегом или веткой. Сравнивает версии сам apm.

- Хук только сообщает: `apm.yml`, `apm.lock.yaml` и установку он не меняет, `apm install` не запускает.
- Без `apm.yml` хук молчит.
- Без `apm.lock.yaml` сообщает, что проверка не сделана: `apm outdated` сверяет версии с lock-файлом.
- Если `apm outdated` завершился с ошибкой или в PATH нет `apm`, хук сообщает, что проверка не сделана.
- Сессия ждёт хук, таймаут не задаётся: `apm outdated` занимает 2–3,5 с, почти всё — сеть.
- Глобальные скиллы `~/.apm` не проверяются.

### Доступ к gitlab

К gitlab apm ходит по https, даже когда в `apm.yml` записан `git@…`. Без логина по https зависимость молча показана как `unknown`, а не как отставшая. Дайте git логин по https:

```bash
glab auth login --hostname <хост>
git config --global credential.https://<хост>.helper '!glab auth git-credential'
```

`glab auth git-credential` — помощник git, который берёт токен из `glab`; первая команда сохраняет этот токен для хоста.

## Разработка

Обвязка разработки приходит из приватного пакета [skill-kit](https://github.com/xronos-i-am/skill-kit): без доступа к нему `make setup` не пройдёт, а `make install` пройдёт.

| Команда | Когда |
| --- | --- |
| `make setup` | после клона, после правки скилла и чтобы взять свежий skill-kit. Если он обновился, поднимает его версию в `apm.yml` — закоммитьте |
| `make release [minor\|major]` | выпустить версию скилла: тег `vX.Y.Z` и push |

Раскладка каталогов:

- исходник скилла, его скриптов и ассетов — `.apm/skills/<скилл>/`, правка идёт туда;
- `.claude/`, `.agents/` и `.opencode/` собирает `make setup` из `.apm/`, правки в них затираются следующим `make setup`;
- `apm_modules/` — зависимости пакета, а не код этого репозитория.
